# 문서와 물어보기

## 문서 보기

`DocumentsPage.tsx`가 사업이 골라졌는지 확인하고 목록과 보기 화면을 연결합니다.

| 파일 | 역할 |
| --- | --- |
| `DocumentList.tsx` | 종류 필터, 제목과 본문 검색, 목록. 외부 링크 문서는 새 탭에서 열림 |
| `DocumentViewer.tsx` | 앱 안 PDF 보기, 쪽 이동, 전체 화면, 개정 표시, 버전 기록. 쪽은 `?page=`로 유지 |
| `DocumentPassages.tsx` | 본문 검색 결과(쪽수 칩, 검색어 강조, 더 보기) |
| `DocumentSearchPanel.tsx` | 문서 보기의 "이 문서에서 찾기"(데스크탑은 옆 패널, 모바일은 검색 아이콘) |
| `useDocumentSearch.ts` | 본문 검색 요청, 입력 후 0.4초 기다리기, 이어 불러오기 |
| `documentData.ts` | 종류 목록, 안내 문구, 색인 상태 표시 |
| `DocumentVersionsDrawer.tsx` | 버전 기록, 지난 판 보기, 관리자는 복원 |

### 본문 검색

문서 목록의 검색칸은 제목과 본문을 함께 찾습니다. 제목이 맞는 문서는 위에, 본문에서 찾은 구절은 아래에 나옵니다.

- 서버는 `POST /api/documents/search`로 구절, 쪽수, 점수를 줍니다. 형식은 문서 API(원 저장소 계약서)를 따릅니다.
- 검색어는 2글자 이상이고 500자까지입니다. 10개씩 불러오고 "더 보기"로 이어 받습니다.
- 점수가 0.5보다 낮은 구절은 숨깁니다(`MIN_PASSAGE_SCORE`). 서버가 낮은 점수의 구절도 내려 주기 때문에 프론트에서 정한 값입니다. 11-25 기준 NLP 임베딩 모델로 재 보니 말이 안 되는 검색어는 최고 0.46, 관련 있는 검색어는 첫 결과가 대체로 0.55 이상이었습니다. 점수는 NLP가 소수 넷째 자리로 반올림한 값이고, 임베딩 모델을 바꾸면 다시 재야 합니다.
- 구절을 누르면 `/documents/<id>?page=<쪽>`으로 그 쪽이 열립니다.
- 본문을 아직 읽지 못한 문서(`notIndexedDocumentIds`)가 있으면 "제목으로만 찾아요"라고 알려 줍니다.
- "이 문서에서 찾기"는 서버에 문서 하나만 고르는 기능이 없어서, 최대 50개를 받아 이 문서의 구절만 걸러 보여 줍니다. 그래서 문서가 많은 사업에서는 이 문서의 구절이 51위 밖이면 안 보일 수 있습니다. 검색 API가 `documentId`를 받게 되면 서버에서 바로 거를 수 있습니다.

PDF는 브라우저의 PDF 보기를 `iframe`으로 넣은 것이라 검색어를 PDF 안에 형광펜으로 칠할 수 없습니다. 문서 안에서 직접 스크롤하면 위쪽 쪽수도 바뀌지 않습니다.

## 문서 업로드

관리자용 화면입니다.

| 파일 | 역할 |
| --- | --- |
| `AdminDocumentList.tsx` | 목록, 검색과 필터, 교체, 버전, 삭제 확인, 읽기 다시 시도 |
| `DocumentUploadDrawer.tsx` | PDF나 외부 링크 등록. 10MB 이하 PDF만 받고 제목은 파일 이름으로 채움 |
| `DocumentReplaceModal.tsx` | 새 파일로 교체. 현재 판 번호를 같이 보냄 |

업로드는 `metadata`와 `file`을 `FormData`로 보냅니다. 교체와 복원은 목록의 `contentRevision`을, 삭제는 삭제 확인 정보의 `contentRevision`을 같이 보냅니다. 삭제한 문서와 같은 제목으로 새 문서를 등록할 수 있습니다.

## 물어보기

`AskPage.tsx`가 대화 상태를 들고 있습니다. 고른 사업으로 질문을 보내고, 응답의 `conversationId`를 같은 대화의 다음 질문에 씁니다. 새 대화를 시작하거나 사업을 바꾸거나 로그인이 풀리면 대화를 비웁니다.

| 파일 | 역할 |
| --- | --- |
| `BotMessage.tsx` | 응답 말풍선. 즉답, 되묻기 후보와 해당 없음, 답 없음, 개인정보 경고, 오류 |
| `EvidenceView.tsx` | 근거 표시. 등록 안내와 문서 구절, 문서 보기 이동, 관련 화면 열기 |
| `QuestionInput.tsx` | 질문 입력. 500자 제한과 개인정보 패턴 경고 |
| `askData.ts` | 글자 수 계산, 출처 문구, 이동할 화면 경로, 오류 안내 |

응답은 `answered`, `clarify`, `no_answer`, `pii_warning` 네 가지입니다.

- 되묻기에서 후보를 고르면 그 근거를 답으로 보여 주고 `candidateSelected`로 알립니다. "해당 없음"은 `noneSelected`로 알리고, 그 뒤 안내 문구는 응답의 `guide.text`를 그대로 보여 줍니다. 안내 종류가 `contact`이면 입력을 막고 새 대화를 시작하게 합니다.
- 질문은 500자(유니코드 코드 포인트 기준)까지입니다. 전화번호, 주민등록번호, 이메일 같은 형식이 있으면 입력칸에서 먼저 경고하지만 보내기는 막지 않습니다.
- 관련 화면은 앱에 있는 주소만 버튼으로 보여 주고, 관리자 화면은 관리자에게만 엽니다.

요청과 응답 형식은 물어보기 API(원 저장소 계약서)를 따릅니다.
