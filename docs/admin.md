# 관리자 화면

## 사용자와 승인

`UsersPage.tsx`가 역할에 따라 관리자 화면과 조직 단위 리더 화면을 나눕니다. 영역 리더만 가진 사용자는 쓸 수 없습니다. 승인이나 수정이 끝나면 목록을 다시 불러옵니다.

| 파일 | 역할 |
| --- | --- |
| `AdminUsersPage.tsx` | 관리자 화면. 승인 대기, 전체 사용자, 목록 관리 탭 |
| `LeaderUsersPage.tsx` | 조직 단위 리더 화면. 승인 대기와 소속 조직 사용자 역할 추가 |
| `components/UsersTabs.tsx` | 두 화면 공통 탭 |
| `components/PendingUsers.tsx` | 승인 대기. 같은 이름의 활성 사용자가 있으면 안내 |
| `components/AllUsers.tsx` | 전체 사용자, 검색과 조직·역할·상태 필터 |
| `components/UserDrawer.tsx` | 승인과 수정 서랍. 역할, 조직 단위, 영역, 활성 상태 |
| `components/LeaderApprovalDrawer.tsx`, `LeaderRoleDrawer.tsx` | 리더의 승인과 역할 추가. 담당자와 조직 단위 리더만 지정 |
| `components/ListManagement.tsx` | 사업, 업무 영역, 조직 단위, 문서 종류의 이름, 순서, 숨김, 미사용 항목 삭제 |
| `usersData.ts` | 역할 표시, 입력 검사, 요청 형식 변환 |

- 서랍은 역할을 먼저 고르고, 필요한 칸을 그 역할 아래에 보여 줍니다. 역할을 꺼도 입력한 값은 지우지 않습니다.
- 영역은 한 사람에 하나입니다. 영역이 둘인 기존 사용자는 하나로 정리해야 저장됩니다. 목록에 없는 기존 조직과 영역은 "기존 설정"으로 보여 줍니다. 영역 선택지는 사업과 관계없는 `/api/options/user-areas`를 씁니다.
- 목록 관리는 네 목록을 한 번에 불러오고 고친 행만 저장합니다. 순서는 손잡이를 끌거나 위아래 화살표 키로 바꿉니다. 사용 중인 항목은 삭제 대신 숨김만 됩니다. 사업 목록을 저장하면 사이드바 사업 선택도 다시 불러옵니다.
- 두 항목의 이름을 서로 맞바꾸면 한 행씩 저장하는 동안 이름이 겹쳐 서버가 거절합니다. 그래서 한 항목에 임시 이름을 넣어 저장한 뒤 다시 바꿉니다.
- 모바일에서는 표 대신 카드 목록으로 보여 줍니다.

저장할 때 `version`을 같이 보냅니다. 형식은 [인증과 사용자 API](../../../contracts/api/auth.md)를 따릅니다.

## 할 일 템플릿

`TaskTemplatesPage.tsx`가 관리자만 들어오게 막고, 목록과 추가, 수정 화면을 주소로 나눕니다.

| 파일 | 역할 |
| --- | --- |
| `components/TemplateList.tsx` | 단계별 목록, 검색과 영역·기준·상태 필터, 사용 켜고 끄기 |
| `components/TemplateEditor.tsx` | 추가와 수정, 마감 미리보기, 저장 결과 안내 |
| `components/TagManager.tsx` | 태그 추가, 이름 바꾸기, 켜고 끄기 |
| `templatesData.ts` | 기준 이름, 마감 설명, 단계 묶기, 마감 미리보기 계산 |

- 목록은 단계별로 묶고 상시 할 일은 맨 아래에 둡니다. 검색어와 필터는 주소에 담아서 수정 화면에 다녀와도 남습니다.
- 줄을 누르면 수정 화면으로 가고, 사용 스위치는 확인 뒤 바로 저장합니다.
- 수정은 바뀐 칸만 보냅니다. 저장하면 진행 중인 과정에 반영된 건수를 알려 줍니다. 기준을 상시로 바꾸면 일수와 리더 확인을 비웁니다.
- 마감 미리보기는 주말이면 앞 평일로 당겨 보여 줍니다. 공휴일과 회사 휴무일은 서버가 할 일을 만들 때 반영합니다.
- 다른 사람이 먼저 수정했으면 최신 내용을 다시 불러오도록 안내합니다.
- 꺼진 태그는 이미 붙은 템플릿에만 보이고 새로 붙일 수 없습니다. 볼 수 없게 된 연결 문서와 꺼진 영역도 기존 설정은 그대로 보여 줍니다.

형식은 [과정과 템플릿 API](../../../contracts/api/courses-and-templates.md)와 [일정과 홈 API](../../../contracts/api/schedule-and-home.md)를 따릅니다.

## 설정 내보내기와 가져오기

`SettingsTransferPage.tsx`가 관리자만 들어오게 막고 내보내기와 가져오기를 나란히 보여 줍니다. 파일은 `SettingsExport.tsx`, `SettingsImport.tsx`, `settingsKinds.ts`입니다.

- 내보내기는 `GET /api/admin/export?kind=...` 응답을 `portal-<kind>.json`으로 저장합니다.
- 가져오기는 같은 파일을 `dryRun=true`로 먼저 검사해 항목 수를 보여 주고, 확인 창을 거쳐 `dryRun=false`로 적용합니다.
- 종류는 파일 안의 `kind`를 그대로 씁니다. 내보내기로 받은 파일이 아니면 고를 수 없습니다.
- 파일을 바꾸면 미리보기를 다시 해야 적용할 수 있습니다.
- 서버는 오류가 하나라도 있으면 아무것도 적용하지 않고, 오류 위치(`fieldErrors`)는 목록으로 보여 줍니다.
- 적용 요청의 응답을 못 받으면 자동으로 다시 보내지 않고, 같은 종류를 내보내 확인하도록 안내합니다.

형식은 [설정 내보내기와 가져오기 API](../../../contracts/api/settings-transfer.md)를 따릅니다.

## 휴무일 설정

`settings/components/HolidaySettings.tsx`는 연도별 공휴일과 회사 휴무일 목록, `HolidayModal.tsx`는 회사 휴무일 추가와 수정 창입니다.

- 공휴일(`source: API`)은 서버가 자동으로 가져오므로 수정과 삭제 버튼이 없습니다.
- 회사 휴무일을 바꾸면 서버가 영향받는 미완료 할 일의 마감을 다시 계산하고, 마감이 바뀐 건수(`deadlineChangedTaskCount`)를 알려 줍니다.
- 수정은 바뀐 칸만 현재 `version`과 함께 보냅니다.
- 설정 가져오기의 `settings` 파일에는 질문 기록 보관 일수만 들어 있습니다.

형식은 [일정과 홈 API](../../../contracts/api/schedule-and-home.md)의 공휴일과 회사 휴무일 절을 따릅니다.

## 서비스 토큰

`service-tokens/components/ServiceTokens.tsx` 한 파일입니다. 고른 사업의 과정 요약만 읽는 `COURSE_SUMMARY_READ` 권한으로 발급합니다.

- 토큰 원문은 발급 응답에서 한 번만 받을 수 있습니다. 그래서 닫기 전까지 창을 유지하고, 복사 버튼과 호출 예시를 같이 보여 줍니다.
- 오른쪽 "발급한 토큰"에 최근 발급 순으로 목록이 나옵니다. 폐기한 토큰은 "폐기됨"과 폐기 시각이 붙고 폐기 버튼이 없습니다.
- 폐기가 끝나면 목록을 다시 불러옵니다. 이미 지워진 토큰이면 404라서 그 사실을 알려 줍니다.

형식은 [연동 API와 서비스 토큰](../../../contracts/api/integration.md)을 따릅니다.
